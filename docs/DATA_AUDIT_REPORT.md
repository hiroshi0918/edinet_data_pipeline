# データベース実データ突合レポート

調査日: 2026-08-16  
対象: 運用正本 PostgreSQL `edinet_db`（Alembic `0006_add_employee_info_metrics`）、分析スナップショット DuckDB / Parquet、同梱サンプル CSV ZIP

---

## 1. 結論

**運用 DB は「今の抽出器が raw CSV から出す値」と一致している。壊れた行の混入やスナップショットの陳腐化は見当たらない。一方で、「有報の世間一般の連結ヘッドライン」とは一致しないケースが財務・人的資本の両方に残る。**

| 判定 | 内容 |
| --- | --- |
| 一致 | スキーマ・参照整合性・DuckDB/Parquet との件数・合計値 |
| 一致 | 処理済み 11,364 件すべてに raw 事実と evidence がある。失敗・未処理ゼロ |
| 一致 | raw 再抽出 84 件が格納値と完全一致。財務 evidence 45,093 件も格納値と一致 |
| 一致 | サンプル 4 書類（ビジネスコーチ / リーディング証券 / トヨタファイナンス / SDS HD）の ZIP ↔ DB |
| 注意 | 売上は開示上の実数だが、連結/個別・営業収益/売上高の粒度が混在する |
| 不一致 | 提出会社×全労働者の男女賃金差異のうち **20% 未満の 1,512 / 1,515 件が text_fallback**。注記番号などを拾っている |
| 欠損 | サンプル `S100PUDO`（セプテーニ 2022-12 提出）は DB に無い。2022 年提出の有報はパイプライン対象外 |

旧バグ「女性管理職比率 = 男性育休取得率」は再発していない（提出会社×全労働者で 54 / 5,649 = 0.96%。うち大半は両方 0）。

`NetSalesSummaryOfBusinessResults`（当期）がある 10,194 書類のうち、格納売上と一致したのは **9,630 件（94.5%）**。残 520 件は、経営指標等の個別売上ではなく、損益計算書側の連結「売上高」など別行を first-wins で拾っている。

花王・クボタ・カゴメなどでは、格納値のほうが経営指標等より大きく、公式の **連結** 売上に近い。トヨタでは逆に経営指標等（個別）が採用されている。規則は安定しているが、連結/個別は書類ごとに揺れる。

| トヨタファイナンス | 2025/03 | 2,855 億 | 営業収益、経営指標等 | サンプル CSV と同値 | 一致（金融は営業収益が本体） |

トヨタ FY2024 の経営指標等に載っている売上タグは `NetSalesSummaryOfBusinessResults = 17575593000000` だけ。抽出器は開示どおり拾っている。45 兆は IFRS の連結営業収益で、別要素である。

キーエンス FY2024 平均年間給与 20,670,730 円、平均年齢 35.2 歳、勤続 11.5 年は、国内開示として妥当なレンジ。

### 9.1 抽出レイヤの内訳

| matched_by | 件数 | 主な指標 |
| --- | ---: | --- |
| `element_id_match` | 153,791 | 人的資本 3 指標 + 従業員情報 |

| `llm_fallback` | 0 | LLM は未使用 |

Layer 1 が主経路。財務はすべて項目名マッチ。

### 9.2 要素 ID は実データと一致する

Layer 1 を 300 書類で再計算すると、格納値は「全観測の中央値」と一致する。前期を混ぜて当期とずれるのは 300 件中 2 書類（同一企業 E03554 の 2 期）だけ。影響は局所的。

ビジネスコーチ・SDS の女性管理職は CSV の `pure` 値 ×100 そのもの。

### 9.3 text_fallback が提出会社×全労働者を汚染している

男女賃金差異は法令上「女性の賃金 ÷ 男性の賃金 × 100」なので、健全な分布はおおむね 40〜90% である。

提出会社 × 全労働者（ダッシュボード既定次元）:

| 賃金差異 | 件数 | うち element_id | うち text_fallback |
| --- | ---: | ---: | ---: |
| < 20% | 1,515 | **3** | **1,512** |
| 40〜100% | 6,646 | 6,629 | 140 |
| > 100% | 37 | （Layer 1 の可能性が高い） | |

20% 未満のほぼ全件がテキストフォールバックである。実例:

- **トヨタファイナンス** 7.48 / 7.69: 従業員の状況テキスト先頭の「(注) 1.」「2.」などから数値を拾っている。要素 ID の賃金差異タグは無い。
- **SDS HD** 全労働者 1.0: テキスト中の注記番号。正規雇用は要素 ID `0.593` → **59.3%** で妥当。
- **セプテーニ HD** 提出会社 2.3 / 3.0: 同じくテキスト。連結子会社側には `0.727` → 72.7% などの要素 ID がある。ダッシュボード既定次元では誤値が前面に出る。

平均給与・勤続・年齢の外れ値検査（給与 10 万〜5,000 万、勤続 0〜60、年齢 15〜100）は **0 件**。光通信 3,518 万円、キーエンス 2,067 万円、北浜キャピタル 50 万円などはレンジ内で、持株・少人数会社の低給与もあり得る。

男性育休 > 100% は 423 件。上限クリップ 200% ちょうどが目立つ。法令の算定（分母が当年出産、分子に前年開始の育休を含む）では 100% 超は起こり得る。全件が誤りとは言えない。

## 10. 総合判定

```text
CSV ZIP / raw_edinet_facts
        │  現行 extractors
        ▼
 PostgreSQL 格納値     ← ここまでは一貫している
        │  export-analytics
        ▼
 DuckDB / Parquet     ← 正本と数値まで一致
        │
        ▼
 ダッシュボード既定次元（提出会社 × 全労働者）
        │
        ├─ 財務: 経営指標等の実数。ただし連結ヘッドラインとは限らない
        └─ 人的資本: Layer 1 は実数。タグが無いと text_fallback が
                    注記番号を賃金差異として出す
```

「DB がファイルと食い違っている」のではなく、「抽出方針がヘッドライン連結値や、タグの無い人的資本を正しく表さない」ことが本体である。

## 11. 推奨

2026-08-16 に実装済み。反映は `alembic upgrade head` → `edinet reprocess` → `edinet export-analytics --format both`。

1. **提出会社×全労働者の賃金差異で `text_fallback` かつ 20% 未満の行を採用しない**
   正規雇用の Layer 1 値があるならそちらを見せる、無ければ NULL。
2. **売上の要素 ID を Layer 1 化する**
   IFRS `KeyFinancialData` / `RevenueIFRSSummaryOfBusinessResults` / `NetSalesSummary...` を優先。
3. **人的資本を `doc_id` 単位で保持する**
   変則決算の後勝ち上書きを止める (`0007_human_metrics_by_doc_id`)。
4. **2022 年提出分は README に対象期間を書き、`import-local` / `backfill` で足せる**
5. **Layer 1 人的資本は当期のみ**
   前期を中央値に混ぜない。

## 12. 再現コマンド

調査に使った接続先は docker-compose 既定の `postgresql://user:password@localhost:5432/edinet_db`。DuckDB は `artifacts/analytics/edinet_analytics.duckdb`。

```sql
-- ステータス
SELECT status, COUNT(*) FROM financial_reports GROUP BY status;

-- DuckDB との突合用
SELECT COUNT(*), SUM(sales)
FROM (
  SELECT DISTINCT ON (doc_id) doc_id, sales
  FROM vw_company_year_metrics
  WHERE scope = 'reporting_company' AND worker_type = 'all'
  ORDER BY doc_id
) t;

-- text_fallback 汚染
SELECT COUNT(*)
FROM human_capital_metrics
WHERE scope = 'reporting_company' AND worker_type = 'all'
  AND gender_wage_gap < 20;
```
